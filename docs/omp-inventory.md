### session — 91 features (18 core)
- **session-jsonl-format** [~/.omp/agent/sessions/<encoded-cwd>/<timestamp>_<sessionId>.jsonl] Persist a session as JSONL: a fixed-width 256-byte `{"type":"title"}` slot line, then the `type:"session"` header line, then one `SessionEntry` object per line; loaders strip the physical title slot and fold its title/titleSource into the logical header, and accept legacy header-first files with no slot.
- **session-header-schema** [first JSONL line: {"type":"session",...}] Header carries `type:"session"`, `version` (current 3), `id`, `timestamp`, `cwd`, optional `title`, `titleSource` (`auto`|`user`), `additionalDirectories` (normalized+deduped extra roots), `previousSessionFiles` (prior absolute paths after successful moves), `providerPromptCacheKey`, and opaque `parentSession` lineage string.
- **entry-taxonomy** [SessionEntry union in src/session/session-entries.ts] Every non-header entry has `{type,id(8-char),parentId(string|null),timestamp}`; the union is exactly: message, thinking_level_change, model_change, service_tier_change, compaction, branch_summary, reset_boundary, custom, custom_message, label, title_change, ttsr_injection, credential_pin, session_init, mode_change — each with the documented payload shape.
- **session-loader** [src/session/session-loader.ts] `loadEntriesFromFile(path)` returns [] on ENOENT; uses a streaming JSONL reader for files ≥8 MiB and a full text read otherwise; tolerates non-parseable lines via a lenient parser; strips the title slot; returns [] when the first logical entry is not a valid header (`type!=="session"` or non-string `id`).
- **session-path-layout** [src/session/session-paths.ts; ~/.omp/agent/] Derive the session bucket from the canonicalized cwd (symlink aliases share a bucket): `-<relative>` under home, `-tmp-<relative>` under temp root, `--<encoded-absolute>--` otherwise, with separators replaced by `-`; blobs at ~/.omp/agent/blobs/<sha256>; on access, best-effort migrate legacy hashed buckets (`<scope>-<basename>-<sha256(cwd)>`) and older `--<home-encoded>-*--` spellings back to path-encoded names.
- **append-write-pipeline** [SessionManager append* methods] Each completed entry updates memory and is handed to storage synchronously inside the append call once the file gate is crossed; streaming partial text is never persisted until the completed message is appended; concurrent completed appends supersede an in-flight atomic rewrite with an authoritative full-body rewrite.
- **flush-durability-ops** [SessionManager.flush() / flushSync(); SessionStorageWriter{append,appendSync,flush,flushSync,isOpen,close,getError}] `flush()` drains async disk/storage queues and the open writer; `flushSync()` performs synchronous draining/full rewrite where supported; neither performs fsync, so the guarantee covers software crashes only; writer close propagates the first meaningful error.
- **session-entry-index** [SessionEntryIndex / SessionManager.getTree()] Maintain runtime indices in lockstep with the entry journal: `entriesById` map, `children` parent→children adjacency (including a null-parent bucket), resolved `labels` map, current `leaf` pointer, and running usage totals; expose `getEntries()` in insertion order, `getBranch(fromId?)` (root→node path), `getTree()` (SessionTreeNode{entry,children,label} with children sorted oldest→newest, orphan/self-parent/null-parent entries as roots), `getChildren(parentId)`, `getLabel(id)`.
- **leaf-movement-primitives** [SessionManager.branch/resetLeaf/branchWithSummary] Exactly three primitives: `branch(entryId)` validates existence and moves `leafId` only (no entry written, cannot take null); `resetLeaf()` sets leafId=null so the next append is a root with parentId=null; `branchWithSummary(branchFromId|null, summary, details?, fromExtension?)` sets the leaf then appends a `branch_summary` child, persisting `fromId:"root"` when the target was null.
- **build-session-context** [src/session/session-context.ts] `buildSessionContext(entries, leafId?, byId?, options?)` returns the LLM context: null leaf → empty; explicit leaf else last entry; walk parentId to root stopping on a repeated id (cycle bound) then reverse; derive resolved+configured thinking, per-family service tier, role→model map (`role ?? "default"`; assistant-message inference is legacy fallback only until an explicit default), deduped injectedTtsrRules, and mode/modeData (default `"none"`); pick the emission boundary (latest reset_boundary wins, else latest compaction emits summary + kept/post-compaction messages); convert message, custom_message and branch_summary entries into messages while other types only affect replay state.
- **dangling-toolcall-sanitization** [buildSessionContext internals] When rebuilding model context, remove tool calls with no paired result (unless explicitly retained for a mid-turn transcript), neutralize protected reasoning metadata on rewritten turns, and drop unsafe aborted/error assistant turns together with their paired tool results.
- **new-session** [/new] `/new` starts an empty conversation, switching session identity and assigning a new transcript path in persistent mode; the `/new` boundary is preserved across `--continue` by writing a `fresh` breadcrumb whose lazily-created JSONL does not yet exist.
- **switch-session-runtime** [AgentSession.switchSession(sessionPath)] `AgentSession.switchSession(path)` is the guarded in-process transition: emit cancellable `session_before_switch{reason:"resume",targetSessionFile}` → disconnect agent events, abort in-flight work, run pre-switch reconciler → flush bash/session writes and snapshot rollback state (manager, messages+all queues, model/thinking/tier, tools/prompts, provider/cache ids, memory promotion, checkpoint/rewind) → clear queues, drain/detach advisor recorders for a different file → `setSessionFile()` → sync ids/memory keys/display context/checkpoint → emit `session_switch` → replace messages, reset advisors, sync todos, close provider sessions → restore model, synthetic abort for interrupted turns, restore thinking/tiers → reset memory/tool state → reconnect events, run session-switch reconciler, refresh workspace-root prompt block (errors logged, not rolled back) → restore advisor cost, finish bash transition, notify session-change callbacks, return true. Any throw before commit restores every snapshotted field, reconnects and re-reconciles, then rethrows. It never creates a session file.
- **set-session-file-recovery** [SessionManager.setSessionFile()] `setSessionFile(path)` updates the breadcrumb, loads/migrates/blob-resolves/indexes entries, and adopts the recorded cwd; an empty loader result (ENOENT, malformed header, or unreadable entries) is treated as an empty session and a brand-new initialized session is materialized at that exact path — recovery, not failure; genuine I/O errors still propagate.
- **session-listing-discovery** [src/session/session-listing.ts; SessionManager.list/listAll/getRecentSessions/findMostRecentSession] Two scan pipelines over the cwd bucket: `getRecentSessions(dir,limit=4)` reads only a 4 KiB prefix and returns `{path,name,timeAgo}` sorted by mtime desc; `list(cwd,sessionDir?)`/`listAll()` read a 4 KiB prefix plus a bounded 32 KiB tail and return `SessionInfo{path,id,cwd,title/parent metadata,dates,size,message previews/count,status}` sorted by modified desc, where status ∈ complete|interrupted|aborted|error|pending|unknown. Scans are stat-keyed and cached, large sets use bounded parallel workers, `listSessionsReadOnly` is the non-mutating variant, and normal per-directory scans recover the newest orphaned EPERM `.bak` when its primary JSONL is missing.
- **compaction-entry-and-boundary** [compaction entry; compaction.keepRecentTokens=20000] `CompactionEntry{summary,shortSummary?,firstKeptEntryId,tokensBefore,details?,preserveData?,fromExtension?}` is appended on the leaf; `prepareCompaction()` considers only entries after the previous compaction (`boundaryStart = prevCompactionIndex+1`), adapts `keepRecentTokens` (default 20000) by measured usage ratio, and runs `findCutPoint()`; valid cut points are message entries with roles user/assistant/bashExecution/hookMessage/branchSummary/compactionSummary, `custom_message` entries, and `branch_summary` entries — never a `toolResult`; non-message metadata entries immediately before the cut are pulled into the kept region by moving the cut index backward until a message or compaction boundary.
- **compaction-triggers** [/compact; compaction.thresholdPercent=-1 / thresholdTokens=-1 / midTurnEnabled=true / idleEnabled=false / idleThresholdTokens=200000 / idleTimeoutSeconds=300] Six paths: manual `/compact [instructions]`; overflow recovery (same-model assistant error detected as context overflow and not older than the latest compaction — remove the failing message, try context promotion first, else compact with reason `overflow`, willRetry true, then schedule `agent.continue()`); incomplete-output recovery (`stopReason==="length"`, reason `incomplete`, willRetry true, handoff strategy allowed); post-turn threshold maintenance (`resolveThresholdTokens`, reason `threshold`, willRetry false); mid-turn threshold maintenance at safe tool-loop boundaries when `compaction.midTurnEnabled!==false`; and idle maintenance (`runIdleCompaction()`, reason `idle`, no auto-continue) when not streaming or already compacting.
- **compaction-persist-and-rebuild** [AgentSession.compact()] After summary generation (or a hook-supplied summary): append the CompactionEntry, rebuild display context from the active leaf, replace live agent messages with the rebuilt context, synchronize active todo phases from the rebuilt branch, close provider sessions whose history was rewritten, and emit `session_compact`.

### providers — 90 features (27 core)
- **Provider catalog descriptor table** [packages/catalog/src/provider-models/descriptors.ts → CATALOG_PROVIDERS] A single static table maps each provider id to `defaultModel`, ordered `envVars` for API-key fallback, a model-manager factory, `allowUnauthenticated`, `dynamicModelsAuthoritative`, `catalogDiscovery` metadata, and `specialModelManager`; the `KnownProvider` union, default-model map, and provider descriptor list are all derived from it (never hand-maintained).
- **Provider auth-registry definitions** [packages/ai/src/registry/<id>.ts + registry.ts `ALL`] One declarative `ProviderDefinition` per provider (`id`, `name`, `available`, `showInLoginList`, `envKeys`, `allowsMissingApiKey`, `prepareRequest`, `mapSimpleOptions`, `prepareModelDiscovery`, `login`, `refreshToken`, `getApiKey`, `storeCredentialsAs`, `callbackPort`, `pasteCodeFlow`) registered in an ordered `ALL` array; array order is the `/login` list order, and the `OAuthProvider` union, env-key map, refresh dispatch, and callback-port map derive from it.
- **Model registry assembly pipeline** [ModelRegistry.refresh() / getAll() / getAvailable()] On refresh, load bundled catalog → load `models.yml`/`models.yaml` → apply provider overrides (`baseUrl`,`headers`,`disableStrictTools`) to built-ins → apply `modelOverrides` per provider+model id → merge custom `models` (same provider+id replaces, else append) → merge cached/runtime-discovered models, then re-apply model overrides; `getAll()` returns everything loaded, `getAvailable()` filters to selectable.
- **Model availability rule** [ModelRegistry.getAvailable()] A model is selectable iff its provider id is NOT in the effective `disabledProviders` list AND (the provider is keyless — implicit local engine or `auth: none` — OR credentials resolve); disabled is checked strictly before credentials so no key, OAuth session, env var, or `models.yml` `apiKey` can re-enable a disabled provider.
- **Credential resolution ladder** [AuthStorage.getApiKey* / ModelRegistry.getApiKey] Resolve a provider key by first match: (1) runtime override (`--api-key`, never persisted), (2) `models.yml` `providers.<id>.apiKey` config key, (3) stored OAuth credential (refreshed on demand), (4) login-sourced stored API key, (5) provider env var incl. `.env`-loaded values, (6) other stored API key (e.g. broker-migrated), (7) `models.yml` fallback resolver; keyless providers return a `kNoAuth` sentinel.
- **Provider→environment-variable map with ordered fallbacks** [descriptor `envVars` / ProviderDefinition `envKeys` / getEnvApiKey(provider)] Each provider declares one or more env var names checked in order (e.g. `anthropic`: `ANTHROPIC_OAUTH_TOKEN` then `ANTHROPIC_API_KEY`; `moonshot`: `MOONSHOT_API_KEY` then `KIMI_API_KEY`; `coreweave`: `COREWEAVE_API_KEY` then `WANDB_API_KEY`), with computed resolvers (`envKeys`) overriding the plain list for probe-based providers (Vertex ADC, Bedrock chain, Anthropic Foundry).
- **models.yml custom provider schema and validation** [~/.omp/agent/models.yml (fallback models.yaml; models.json auto-migrated)] Root accepts only `providers:`; a provider with non-empty `models` requires `baseUrl`, `apiKey` (unless `auth: none`), and `api` at provider or every model level; an override-only provider (no models) requires at least one of `baseUrl`,`apiKey`,`auth: none`,`headers`,`compat`,`disableStrictTools`,`modelOverrides`,`discovery`,`remoteCompaction`; models require `id` with positive `contextWindow`/`maxTokens` if present; a schema/YAML failure keeps built-in models running and exposes the error via `ModelRegistry.getError()` surfaced in UI.
- **Model selector parsing and initial-model resolution** [`--model`, `--models`, legacy `--provider`, `/model`, `omp models`] Parse exact `provider/modelId`, bare model id (provider inferred), fuzzy/substring, glob scope patterns in `--models` (`openai/*`, `*sonnet*`), and an optional `:thinkingLevel` suffix (`off|minimal|low|medium|high|xhigh|max`); initial model picks in order: explicit CLI provider+model → first scoped model (when not resuming) → saved default → known provider defaults among available → first available.
- **Interactive login/logout slash commands** [`/login`, `/login <provider>`, `/login <redirect-url>`, `/logout`] `/login` opens the OAuth/key provider selector (ordered by registry `ALL`, filtered by `available` and `showInLoginList`), `/login <provider>` jumps directly, `/login <redirect-url>` completes a paste-code flow; `/logout` opens a selector that deletes stored credentials for a provider. Logins are provider-scoped — authenticating one provider never authenticates another — and a disabled provider stays disabled with valid stored auth.
- **OAuth token refresh and expiry handling** [ProviderDefinition.refreshToken / AuthStorage refresh] `refreshToken` per provider (omit for static tokens → credentials returned unchanged), refresh triggered by a per-provider skew before expiry (e.g. 60 s for Gemini CLI/Antigravity/Vertex, 5 min broker default), single-flighted per credential id so a slow refresh cannot re-trigger, with definitive failures (`invalid_grant`, `invalid_token`, `revoked`, non-blip 401/403) disabling the credential and transient failures (timeout/ECONNREFUSED/fetch failed) left for the next sweep. Anthropic additionally enforces an absolute 30-day grant TTL requiring interactive re-login regardless of refresh rotation.
- **Local SQLite auth store** [~/.omp/agent/agent.db] Stored OAuth and API-key credentials live in `~/.omp/agent/agent.db` (relocated with `PI_CODING_AGENT_DIR`), with schema-versioned tables, per-credential disable with recorded cause, provider/scope rate-limit blocks, credential dedup by parsed inner token for compound JSON credentials, and a `shared`-scope compatibility mirror maintained by triggers for pre-meter binaries that current APIs must not double-count.
- **Unified stream event contract** [AssistantMessageEvent / AssistantMessageEventStream] Every provider emits the same `AssistantMessageEvent` sequence: `start`, block triplets `text_start/text_delta*/text_end`, `thinking_start/thinking_delta*/thinking_end`, `toolcall_start/toolcall_delta*/toolcall_end`, complete `image_end`, and exactly one terminal `done{reason: stop|length|toolUse}` or `error{reason: aborted|error}`. The event stream delivers events immediately in push order with no batching or merging; `done`/`error` resolves `result()` to the final assistant message, `fail(error)` rejects iteration and `result()`, and `end()` without a final result rejects `result()` rather than hanging.
- **Streaming tool-argument JSON accumulation** [parseStreamingJson / parseStreamingJsonThrottled (STREAMING_JSON_PARSE_MIN_GROWTH=256)] Providers append argument fragments to an internal `partialJson` buffer and re-parse via a throttled parser that skips re-parsing until ≥256 new bytes have arrived (bounding mid-stream cost from quadratic to linear); parsing tries `JSON.parse`, falls back to a relaxed/repairing parser for incomplete fragments, and returns `{}` on total failure so malformed deltas never crash the stream. The parse at `toolcall_end` is unconditional and authoritative, after which `partialJson` is stripped.
- **Layered cancellation** [options.signal / AgentSession.abort()] Cancellation propagates as: `options.signal` into the provider client call → provider wrapper forcing the error path with `stopReason: "aborted"` after the stream loop → agent loop checking `signal.aborted` before each provider event and synthesizing an aborted assistant message from the latest partial → `AgentSession.abort()` → `agent.abort()`. Tool execution cancellation is separate: runners use `AbortSignal.any([agentSignal, steeringAbortSignal])` so steering interrupts can abort remaining tools while preserving already-produced results.
- **OpenAI Chat Completions transport** [api: openai-completions] POST JSON + SSE against `/chat/completions` using in-repo HTTP/SSE transport (no vendor SDK): decode `ChatCompletionChunk` frames, normalize `delta.content` whether string or array of text parts, take the first non-empty of `reasoning_content`/`reasoning`/`reasoning_text` per chunk, track `tool_calls[].index` for parallel calls, attach `reasoning_details` encrypted signatures to `toolCall.thoughtSignature`, promote `finish_reason: "stop"` to `toolUse` when structural or healed tool calls exist, and parse usage from `chunk.usage` or `choice.usage`.
- **Anthropic Messages transport** [api: anthropic-messages] POST `/v1/messages` over SSE with an in-repo HTTP client (retry + timeout, honoring `retry-after-ms`/`retry-after`): handle `message_start` (usage init), `content_block_start` (text/thinking/tool_use/redacted_thinking), `content_block_delta` (`text_delta`, `thinking_delta`, `signature_delta` updating the signature with no event, `input_json_delta`), `content_block_stop`, `message_delta` (stop reason + final output tokens), `message_stop`, `ping`. ### tui — 78 features (23 core)

- **focus-and-cursor-marker** [`TUI.setFocus()`, `CURSOR_MARKER`, `Focusable`] `Focusable { focused: boolean; setUseTerminalCursor?(b) }` is separate from `Component`; `TUI.setFocus(c)` routes input and toggles `focused`; focused components embed `CURSOR_MARKER` inside their rendered text and the engine extracts/strips it and positions the hardware cursor there — there is no `getCursorPosition()` API. Cursor is parked at real content bottom (not padded window bottom) and clamped before movement.
- **append-only-scrollback-ledger** [`TUI` frame pipeline / commit ledger (packages/tui/src/tui.ts)] Transcript lives on the NORMAL screen (native scrollback/selection/persistence). Engine keeps `committedRows` C (rows `[0,C)` are in terminal history and are never rewritten by ordinary emitters), `windowTopRow` W (frame row mapped to grid row 0; visible window = `[W, W+height)`), and live-region boundary B. For an ordinary unpinned frame `W = max(C, L - height)` and new commit end = `max(C, W)` clamped to frame; only the chunk between old and new commit index is emitted into history. The renderer NEVER probes terminal scroll position on any platform (win32 == POSIX).
- **frame-emitter-classifier** [`#emitFullPaint` / `#emitUpdate` in TUI] Each frame is classified and routed to exactly one of four byte shapes: (1) `#emitFullPaint` = home + committed chunk + window rows (+optional ED3) for initial paint / explicit geometry-session-reset gestures / rebuild; (2) scroll-append = new bottom rows + changed-row range, used only when rows leaving the screen are exactly the commit chunk; (3) in-window diff = relative cursor move + changed-row rewrite when nothing scrolls or commits; (4) seam rewrite = commit chunk + full window rewrite on commit/window re-anchor or hidden-gap backfill. The ordinary update path NEVER emits ED2/ED3 or an absolute cursor home (several terminal families snap scrolled readers to bottom on those).
- **live-region-seam-contract** [`NativeScrollbackLiveRegion` / `NativeScrollbackCommittedRows` / `NativeScrollbackReplay` interfaces] `NativeScrollbackLiveRegion.getNativeScrollbackLiveRegionStart()` returns the first local row that may still mutate; rows before it are declared byte-stable at the current width and are eligible for exactness auditing. `isNativeScrollbackLiveRegionPinned()` keeps the mutable suffix viewport-local (clipped, never snapshotted) instead of committing frozen snapshots as it scrolls off — for replacing dashboards, not append-shaped transcript. Reporting no seam yields shell semantics (whatever scrolls off is final). When multiple root children report a seam the TOPMOST wins, because commits are prefix-only. Companion interfaces: `NativeScrollbackCommittedRows` (container passes committed count to children) and `NativeScrollbackReplay` (component releases layout locks before a destructive replay).
- **transcript-container-seam** [`packages/coding-agent/src/modes/components/transcript-container.ts`] The application-side seam implementation: scan for the first UNFINALIZED transcript block; finalized blocks before it are exact; the live block may extend the exact boundary via `getTranscriptBlockSettledRows()`.
